## Reports wiring (host side)

```ts
import { RemoteContentSource, pinsBundleValidator, localStoragePersistence } from '@in-app-training/sdk';
import { createContentClient } from '@in-app-training/api-client';

const client = createContentClient({
  baseUrl: 'https://internal-training-api.reports/training/v1',
  token: () => reportsAuth.currentAccessToken(),
});

const source = new RemoteContentSource({
  product: 'adopter-c',
  client,
  persistence: localStoragePersistence(),
  validate: pinsBundleValidator(),
  bootBlocking: true, // small pins bundle; blocking makes first-paint deterministic
});

source.on((event) => {
  if (event.name === 'content_bundle_updated') {
    // Pins are re-mounted by the PinsProvider on snapshot change; no
    // Trainer.replaceTours needed here (Reports is pins-only in Sprint 18).
    reportsPinsBridge.refresh(source.snapshot()?.body);
  }
  if (event.name === 'content_bundle_update_failed') {
    reportsErrorTracker.notify(event.payload);
  }
});

await source.start();
```

## Known limitations (deliberate)

- **`zod-to-openapi` still deferred** (T-280 for Sprint 19). Hand-written OpenAPI spec remains the source of truth for the API preview.
- **`createFileContentStore` is single-writer.** File locking is out of scope; adopters running multiple write nodes plug their own DB-backed store against the same `ContentStore` interface.
- **`Trainer.replaceTours` does not migrate an active tour to the new bundle.** Per ADR-0008, the running tour finishes on the bundle it started with. Adopters who want a mid-flight swap must dismiss + re-launch — see Sprint 19 T-281 for a proposed opt-in `interruptOnSwap: true` config.

## Rollback

- Reports: revert `RemoteContentSource` wiring to build-shipped pins (a one-line change). No SDK-side dependency prevents this.
- Reference api-server: revert to `createInMemoryContentStore` (the in-memory reference from Sprint 16). File-store data persists on disk and is not touched.
