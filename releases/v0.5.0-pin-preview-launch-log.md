## What went well

- **PinAnchor got the "target rect follows on any event" story right on the first draft.** Zero anchoring bugs in QA. The MutationObserver-on-body removal path was worth the extra 20 lines.
- **API parity between React and Vue landed identical on both sides.** The two test suites are almost line-for-line mirrors — that's the intent.
- **Existing coverage gates + event-dictionary drift check made the analytics-add pass painless.** T-114 regenerated the dictionary; CI passed once the tests were rewired.

## What went badly

- **The 2px cosmetic occlusion on the avatar pin at mobile width.** A `preferredCorners`-style anchor-position picker for pins (mirroring T-092 for the checklist) would fix it. Deferred to v0.5.1.
- **`pin_shown` dedupe is module-scoped, not user-scoped.** If two `<PinsProvider>` instances mount in the same page (rare — but possible in host apps with multiple app shells), they share dedupe state. Fine for now, worth flagging in the doc.

## Surprises

- **Dismissal rate on `create-project-shortcut` is 9% — lower than expected.** New users seem to want the reminder. If this holds at 30 days, it's a hint that the retro's `create-project → user-menu` drop-off finding (T-091) is real: users want the CTA to be discoverable, even after they've done it once. Argues for keeping the pin dismissible=true but the default keep-showing-until-dismissed behaviour.
- **Zero support tickets in the first hour.** Baseline is ~10/week for "onboarding" tickets; a pin about "where's Create Project" was expected to dent that. It didn't budge — either the pin worked (people find it) or the ticket writers don't use it. Watch through Sprint 10.
